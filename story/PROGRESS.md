## 批次审稿 loop 流程（**两阶段**：章设计 → 扩写）

> 解决"AI 按大纲平铺直叙"的核心机制——章设计文档先于正文产出。
> 详见 `../outline/chapter-designs/TEMPLATE.md`（11 项节拍蓝图）+ `../docs/审稿-checklist.md`（10 条可勾选）+ `../story/BEATS-LIBRARY.md`（6 类节拍样板）。

### 每章流程
```
1. 读 outline/总纲.md 本章条目（含「主角主动决策/行为」列）
2. 写 outline/chapter-designs/chXX-beats.md（11 项节拍蓝图）
3. 强制项自检（不满足不回扩写）：
   - 目标情绪+强度 ✓
   - 信息差（必须是「对手不知道顾生知道」）✓
   - 3-5 节拍 ✓
   - 主角决策点（含放弃备选）✓
   - 章级小代价（具体丢了什么）✓
   - 章末钩子 ✓
   - 对手本章节奏 ✓
   - 伏笔贡献（必须埋/回收的伏笔号）✓
4. 扩写正文（**只回看**章设计的目标情绪+信息差+对手节奏+画面感锚点 4 项，避免机械）
5. 声音回校（对照上一章成稿校对语气）→ 维护本文件「声音锚点」区
6. 自查（用 docs/审稿-checklist.md 的 10 条，5 条一票否决必须全过）
7. Explore agent 合规审稿（**只**做合规检索：设定漂移/铁律违规/伏笔回收）
8. story-review skill 读者冷读（主编视角，判断好不好看）
9. 改 → commit（中文 message）→ 更新本文件 + foreshadow
```

### 审稿明确分工
- **Explore agent** 只做合规审稿（设定漂移/铁律违规/伏笔回收——这些都是检索任务，它能做）。
- **story-review skill** 做主编视角冷读（好不好看——这是判断任务，用 skill）。
- 两者独立，不能合并。

### 章设计文档处理
- 章设计文档（chXX-beats.md）**不 commit 进正文仓库**——它是过程产物，写完即用，扩写完成后不留。
- 但模板（`TEMPLATE.md`）和样板（未来 ch1 写完后的成品章设计，可保留作为后续参考）可以留在 outline/chapter-designs/。
