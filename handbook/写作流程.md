# 写作流程 —— 5-skill 章节流水线（v2 改造版）

> 本文件是**章节生产流水线的总编排**。主线 4 个 skill 顺序执行（planner→writer→format-editor→story-reviewer），按各 skill 的 verdict 路由（含退回）。**每 5 章硬触发一次 arc-editor 做跨章总控**（arc-editor 是第 5 个 skill，周期性触发，不在每章主线）。
>
> **v2 改造核心（治"结构对但平"的病）**：
> 1. story-reviewer 从抽象三问自评 → **红队挑刺制**（强制找茬，说不出3个拍腿瞬间就退）
> 2. chapter-planner 加 **T1/T2/T3 张力强制项**（最大意外/最像要输的一刻/金手指失效配额）
> 3. chapter-writer 加 **三副药**（动作优先/先压后扬/反派可恨配角活人感）
> 4. rules-baseline 加 **金手指铁律 §一·B**（失效硬配额/不是通关码/深看有当时代价）
> 5. 新增 **arc-editor**（跨章总控，每5章查套路重复/爽感曲线/金手指配额/人物腔调/伏笔连贯）

---

## 一、流水线总览

```
1. chapter-planner  →  chXX-beats.md（12强制项：9基础+3张力）
       ↓
2. chapter-writer   →  第N章 标题.txt（2500-3000字）
       ↓
3. format-editor    →  格式合格 / 退 writer / 退 planner
       ↓
4. story-reviewer   →  PASS / 退 writer / 退 planner
       ↓
5. （每5章硬触发）arc-editor → 跨章诊断 / 定向退回单
```

- **顺序固定**：planner → writer → format-editor → story-reviewer。前者是后者的前提。
- **各 skill 自带读取协议**，精确控制读取集，**不要一次性把所有 base/style 全读进上下文**。
- **verdict 路由**：每个 skill 输出三态判定（过/退writer/退planner），主对话按 verdict 决定下一步。skill 自己不串联，由主对话编排。
- **arc-editor 是周期性的**，不在每章流水线里，每 5 章硬触发一次（见 §四）。

---

## 二、章设计强制项（planner 产出标准）

章设计 `chXX-beats.md` 必须填实 **12 强制项**（9 基础 + 3 张力）+ 自检 + 建议项。详见 `output/chapter-designs/template.md`。

### 9 基础强制项（结构骨架）
1. 目标情绪（情绪+强度+读者身体反应）
2. 信息差（对手不知道刘波知道某事）
3. **本章情节·场景级**（叙事骨架，2-4 场景，先于机制项填实）
4. 节拍（3-5 个，标注情绪/张力转折，不复述情节）
5. 主角决策点（两难+选择+放弃的备选）
6. 章级小代价（他丢了什么，具体）
7. 章末钩子（类型+内容）
8. 对手本章节奏（限知视角，只写刘波能看见的）
9. 伏笔贡献（弧线循环进度+埋设/回收伏笔号）

### 3 张力强制项（好看骨架，v2 新增，不达标=退 planner）
- **T1 本章最大意外**：哪个瞬间让读者"没猜到"？填不出=重想。
- **T2 主角最像要输的一刻**：哪个节拍主角看起来要输/死/暴露？填"全程从容"=重想（金手指滥用前兆）。
- **T3 金手指失效方式**：查配额窗口（最近3章），无失效则本章必须设计 1 次（看不全/看错/看不见/反噬）。

> **情节先于机制，张力先于情节**：强制项 3 是"怎么讲故事"，T1/T2 是"怎么讲得好看"。先把情节和张力想清楚，再标情绪/钩子/代价。

## 三、各 skill 的 verdict 路由

### chapter-planner
- **产出**：chXX-beats.md（12 强制项齐全且达标）
- **不产出**：12 项任何一项缺失或不达标 → 报缺口，不产出半成品
- **路由**：产出后交主对话，进 chapter-writer

### chapter-writer
- **产出**：第N章 标题.txt（2500-3000字，自检五项过线）
- **退回上游**：发现 beats 有硬伤（情节走不通/伏笔对不上/T1T2 填不出）→ 停下报主对话退 planner，不边写边改情节
- **路由**：产出后交主对话，进 format-editor

### format-editor（机械审查）
- **PASS（合格）**：字数 2500-3000 + 零 markdown + 破折号 ≤6 + 段落规范 → 进 story-reviewer
- **退 writer（偏短/偏长但情节完整）**：2200-2499 / 3001-3300 → writer 深化/删水，不退 planner
- **退 planner（红线）**：<2200 / >3300 / 段落大面积违规 → planner 重审情节密度

### story-reviewer（红队挑刺 + 三问 + 合规）
- **PASS**：红队挑刺全过（3 拍腿瞬间说得清 + 4 类问题虽指出但可接受 + 反派有力）+ 三问过关 + 合规全过 → 本章定稿，更新台账
- **退 writer（REWRITE）**：红队挑刺不过（拍腿瞬间说不全/主角太从容/反派木偶/动作太少内心独白太多/爽点先压后扬比例错）/ T1T2 没兑现 → writer 局部改，不推倒
- **退 planner（REPLAN）**：情节走不通 / 伏笔对不上 / 金手指配额满 3 章无失效 / T1T2 在 beats 阶段填不出 → planner 改 beats
- **优先级**：能靠改写救的优先退 writer；情节/配额/伏笔硬伤才退 planner

### arc-editor（跨章总控，每5章触发）
- **健康**：五查全过 → 继续推进
- **局部病**：某 1-2 章有问题 → 定向退回单（指到章+skill+问题）
- **系统性病**：套路弥漫/爽感整体塌陷/配额长期不满足 → 暂停推进，回看弧线规划

---

## 四、arc-editor 触发节奏

- **硬触发**：每写完 5 章，主对话**必须**触发 arc-editor（不可跳过）。
- **软触发**：主对话觉得"最近几章腻了/套路了"，随时触发。
- **弧末触发**：每个 Arc 收尾，必触发全弧回看。

arc-editor 做五查（套路重复/爽感曲线/金手指配额/人物腔调/伏笔连贯），详见 `.agents/skills/arc-editor/SKILL.md`。

---

## 五、台账更新（每章 PASS 后必做）

story-reviewer 给 PASS 后，主对话更新：
1. `progress/progress.md`：
   - 正文进度 +1
   - 当前修为/八维/身份（如有进账）
   - 声音锚点区滚动（删最早的，加本章 2-3 行原文锚）
   - **金手指失效配额窗口**记一笔（本章是否有失效，滚动窗口）
2. `progress/foreshadow.md`：本章埋设/回收的伏笔号状态 + 章号

## 六、字数阈值表（format-editor 用）

| 字数（含标点） | 判定 | 路由 |
|---|---|---|
| < 2200 | 红线 | 退 planner（情节密度不足） |
| 2200-2499 | 偏短 | 退 writer 深化 |
| 2500-3000 | 合格 | 进 story-reviewer |
| 3001-3300 | 偏长 | 退 writer 删水 |
| > 3300 | 红线 | 退 planner（情节超载） |

## 七、退回逻辑总结

| 退回方向 | 典型原因 | 处理方式 |
|---|---|---|
| → writer | 动作太少/内心独白多/绝境不深/反派不狠/字数偏短偏长 | 局部改，不推倒 |
| → planner | 情节走不通/伏笔对不上/金手指配额缺/T1T2 填不出/字数红线 | 改 beats，可能波及后续章 |
| → arc-editor 诊断后定向退 | 套路重复/爽感塌陷/人物木偶化（跨章病） | 按诊断报告退具体章的具体 skill |

> **核心原则**：能局部改的不推倒，能改写救的不退 planner。退回是手段不是惩罚，目的是让每一章真正好看。
