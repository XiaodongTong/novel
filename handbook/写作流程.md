# 写小说流程

> 小说生产流程的唯一权威文档。写新章节、扩写、审稿、改稿时按本文执行。
> 本流程由 **4 个 skill 串成流水线**，主对话只做编排与路由，判断由各 skill 输出。

---

## 1. 总览：4-skill 流水线

```
[人工] 规划阶段：维护 base/spine.md + base/arcs/（定走向，不 Agent 化）
              │
              ▼
chapter-planner  (策划) → chXX-beats.md（11 项章设计）
              │
              ▼
chapter-writer   (作家) → 第N章 标题.txt（2500-3000 字正文）
              │
              ▼
format-editor    (编辑) → 字数/格式/段落/破折号 审查
        │  ├─ 合格 ─────────────────────────┐
        │  ├─ 格式违规 / 字数缓冲带 → 退 writer │
        │  └─ 字数红线(<2200 / >3300) → 退 planner│
              ▼                               │
story-reviewer   (总编) ←─────────────────────┘ 故事质量 + 逻辑/合规审查
              ├─ 过稿 → 更新 progress/foreshadow 台账
              ├─ 重要项(展示/节奏) → 退 writer
              └─ 一票否决/逻辑硬伤/伏笔断裂 → 退 planner
```

4 个 skill 都在 `.agents/skills/<name>/SKILL.md`，各自带「读取协议」精确控制读哪些文件。

---

## 2. 各 skill 职责与读取集（控制上下文）

| Skill | 职责（只做这个） | 核心读取 |
|---|---|---|
| **chapter-planner** | 章设计，绝不写正文 | template + rules-baseline + foreshadow + spine(弧段) + arcs(本章) + characters(本章人物) |
| **chapter-writer** | 扩写正文，只回看 beats 的 4 项 | voice-baseline + 格式铁律 + chXX-beats(4项) + 最近1-2章(扫读) |
| **format-editor** | 字数/格式/段落/破折号，不做故事判断 | 格式铁律 + 待审正文 |
| **story-reviewer** | 主编三问+六特质+一票否决 + 合规（设定/铁律/伏笔） | 审稿准则 + rules-baseline + foreshadow + chXX-beats + 待审正文（合规可派 Explore 子 agent） |

**读取集矩阵**（✓必读 ○按需 ✗禁止）—— 落实"各阶段不读无关文件"：

| 文件 | 策划 | 作家 | 编辑 | 总编 |
|---|---|---|---|---|
| progress/progress.md | ✓ | ✗ | ✗ | ○ |
| base/spine.md(当前弧段) | ✓ | ✗ | ✗ | ○ |
| base/arcs/arcX | ✓ | ✗ | ✗ | ○ |
| characters/本章人物 | ✓ | ✗ | ✗ | ○ |
| chapter-designs/template.md | ✓ | ✗ | ✗ | ✗ |
| style/rules-baseline.md | ✓ | ○ | ✗ | ✓ |
| style/voice-baseline.md | ✗ | ✓ | ✗ | ✗ |
| **handbook/格式铁律.md** | **✗** | ✓ | ✓ | ✗ |
| **handbook/审稿准则.md** | **✗** | ✗ | ✗ | ✓ |
| style/beats-library.md | ○ | ○ | ✗ | ✗ |
| base/world/* | ○ | ○(04) | ✗ | ○ |
| progress/foreshadow.md | ✓ | ✗ | ✗ | ✓ |
| 最近1-2章成稿 | ✗ | ✓(扫读) | ✗ | ○ |
| chXX-beats.md | (产出) | ✓(4项) | ✗ | ✓ |
| 待审正文 | ✗ | (产出) | ✓ | ✓ |

**缓存优化**：每个 skill 的「读取协议」固定顺序——**稳定文档在前（跨章不变，命中缓存前缀），章节易变内容在后**。连写多章时，skill body + 稳定文档构成可缓存前缀，只有章节尾巴是新的。

## 3. 单章生产流程（主对话编排视角）

1. **起棒**：确认要写第 N 章。触发 chapter-planner，给它章号。
2. **策划产出**：chapter-planner 读完定位/人物/规则，产出 `chXX-beats.md`（11 项）。8 强制项不齐 → 它会报缺口，补齐再产出。
3. **进入扩写**：章设计就绪，触发 chapter-writer。它只回看 beats 的 4 项扩写正文，产出前自检字数/格式/破折号。
4. **格式审查**：触发 format-editor。它量字数、查格式/段落/破折号，输出三态判定。
5. **按编辑 verdict 路由**（见 §4 字数阈值表 + 退回逻辑）。
6. **格式合格后**：触发 story-reviewer。它做主编三问+六特质+合规，输出三态判定。
7. **按总编 verdict 路由**（见 §5 退回逻辑）。
8. **过稿**：更新 `progress/progress.md`（进度+1、修为/八维、声音锚点滚动）+ `progress/foreshadow.md`（伏笔状态+章号）。

> 主对话**只做路由**：读 skill 输出的 verdict，决定下一棒是谁。判断本身由 skill 完成。

---

## 4. 字数阈值表（format-editor 的路由核心）

针对 2500-3000 字（含标点）目标：

| 字数（含标点） | 判定 | 路由 | 理由 |
|---|---|---|---|
| **< 2200** | 情节不足 | **→ planner** | 补字变灌水，需在章设计层补节拍/场景 |
| 2200–2499 | 偏短 | → writer | 深化现有节拍细节，不加情节 |
| **2500–3000** | **合格** | → story-reviewer | 进故事审查 |
| 3001–3300 | 偏长 | → writer | 删水收紧，不动结构 |
| **> 3300** | 情节超载 | **→ planner** | 砍节拍/重构，否则失衡 |

- **红线**：< 2200 或 > 3300 = 结构问题，回策划；**缓冲带** = 执行问题，回作家。
- markdown / 段落规范 / 破折号>6 违规 → 一律退 writer（哪怕字数合格）。
- 字数是**最高优先级路由信号**：字数触红线直接定路由，先于其它格式问题。

## 5. 退回逻辑总表

| 审查方 | 问题类型 | 退回到 |
|---|---|---|
| 编辑 | markdown/段落/破折号违规 | writer |
| 编辑 | 字数缓冲带(2200-2499 / 3001-3300) | writer |
| 编辑 | 字数红线(<2200 / >3300) | planner |
| 总编 | 一票否决(角色不在乎/冲突不升级/结尾不成立) | planner |
| 总编 | 逻辑硬伤/设定漂移/铁律违规/伏笔断裂 | planner |
| 总编 | 重要项(展示不足/节奏拖沓) | writer |
| 总编 | 加分项(主题直白/语言平庸) | writer 微调 |

**判断准则**：问题是"情节设计层面"（换个写法救不了，得重设节拍/冲突）→ 退 planner；是"执行层面"（情节对，只是没写好）→ 退 writer。

## 6. 章设计强制项（chapter-planner 产出标准，8 项不满足不得扩写）

1. 目标情绪 + 强度明确（情绪类型 + 1-5 强度 + 读者身体反应）。
2. 信息差明确，必须是「对手不知道刘波知道」。
3. 3–5 个核心节拍明确（每个一句话说清）。
4. 主角决策点明确（两难 + 选择 + 放弃的备选）。
5. 章级小代价明确（具体丢了什么）。
6. 章末钩子明确（类型 + 内容）。
7. 对手本章节奏明确（**限知视角**：只写刘波能看见的部分）。
8. 伏笔贡献明确（弧线循环进度 + 埋设/回收的伏笔号 G1/E1/W1/C1/F1）。

> 详见 `output/chapter-designs/template.md` 的 11 项（8 强制 + 3 建议）。

---

## 7. 扩写时只回看四项（chapter-writer 执行标准）

扩写正文时，chapter-writer 只回看 chXX-beats.md 的：

1. 目标情绪
2. 信息差
3. 对手节奏
4. 画面感锚点

其余强制项不回看，避免按表填空变机械。同时对照 `style/voice-baseline.md` 的声音规则。

---

## 8. 章设计文档处理

`output/chapter-designs/template.md` 是模板，必须保留。

`output/chapter-designs/chXX-beats.md` 是过程产物，不 commit。

如需保留样板，使用 `SAMPLE-*.md` 命名，不使用 `chXX-beats.md`。

---

## 9. 合规审查的上下文隔离（story-reviewer 用 Explore 子 agent）

story-reviewer 做**合规审查**（设定漂移/铁律/伏笔回收）时，不要把 world/、foreshadow.md 这些大文件读进主上下文——派 Explore 子 agent 查，只收结论。

**故事判断**（主编三问/六特质）由 story-reviewer 自己做，不能外包——那是主观判断。

两者独立。
